# Cross Read 第一阶段产品与技术方案

## 1. 文档目的

本文档定义 Cross Read 第一阶段（MVP）的产品边界、交互目标、技术结构、安全约束和验收标准。后续实现应以本文档为依据；如需求发生变化，先更新本文档，再调整实现。

## 2. 产品定位

Cross Read 是一个部署在个人 Windows 电脑上的轻量只读文件服务。它不是完整 NAS，也不是在线文档编辑器。

服务自动读取电脑上已发布的普通 Windows SMB 共享，也允许额外指定目录。iPhone 与电脑处于同一 Wi-Fi 时，可以在 Safari 中打开局域网地址，浏览目录并直接阅读文件，无需将大文件预先复制到手机，也无需为 Markdown 等格式安装专用 App。

### 2.1 目标用户

- 电脑中保存了大量学习资料、文档或视频的个人用户。
- 日常更习惯在 iPhone 或 iPad 上阅读内容。
- 只需要读取电脑文件，不需要从网页管理或编辑文件。

### 2.2 核心使用路径

```text
电脑配置共享目录并启动服务
              ↓
页面显示局域网访问地址
              ↓
iPhone Safari 打开该地址
              ↓
选择共享目录并逐级浏览
              ↓
打开文件并进入对应阅读器
```

## 3. MVP 范围

### 3.1 必须实现

#### 服务与配置

- Windows 上可通过命令启动服务。
- 自动发现 Windows 已发布的普通 SMB 共享根目录。
- 自动排除 `ADMIN$`、盘符共享、`IPC$` 等系统和管理共享。
- Windows 新增或取消共享后，刷新网页首页即可同步。
- 支持额外配置一个或多个没有发布为 SMB 共享的根目录。
- 每个共享根目录具有稳定 ID 和用户可见名称。
- 启动时检查目录是否存在、是否可读，并输出清晰的错误信息。
- 默认监听局域网可访问的地址，并明确显示访问 URL。

#### 文件浏览

- 首页展示所有共享根目录。
- 支持逐级进入文件夹和返回上级。
- 使用面包屑展示当前位置。
- 列表项展示名称、类型、大小和最后修改时间。
- 文件夹优先，其余文件按名称排序。
- 支持按文件名搜索当前目录，或递归搜索当前目录及其子文件夹。
- 递归搜索结果显示相对路径，并可直接打开匹配的文件或文件夹。
- 隐藏操作系统文件和配置指定的隐藏项。
- 不支持通过页面修改任何文件。

#### 文件预览

| 类型 | MVP 行为 | 备注 |
| --- | --- | --- |
| Markdown | 渲染标题、列表、表格、引用、代码块、链接、相对图片和 Mermaid 图表 | 渲染结果必须净化 |
| PDF | 页码导航、缩放、文本搜索 | 使用 PDF.js |
| DOCX | 浏览器内只读渲染 | 不保证复杂版式与 Word 完全一致 |
| CSV / XLSX | 单元格表格、多工作表切换 | 不保证复杂样式、图表和交互 |
| PPTX | 按幻灯片显示文字摘要 | 不还原图片、动画和视觉版式 |
| 图片 | 自适应显示、缩放、全屏查看 | 优先支持 JPEG、PNG、GIF、WebP、SVG |
| 文本与源码 | 保留换行；按扩展名语法高亮 | HTML 默认显示源码，不执行 |
| 音频 | 播放、暂停、进度拖动 | 浏览器必须支持文件内部编码 |
| 视频 | 播放、暂停、全屏、进度拖动 | 浏览器必须支持文件内部编码 |
| 旧版 DOC / 未支持类型 | 展示转换建议或“不支持预览”说明 | MVP 不提供下载入口 |

#### 移动端体验

- 以 iPhone Safari 作为首要适配目标。
- 支持常见手机宽度、横竖屏和桌面浏览器。
- 支持刘海屏、灵动岛设备和底部安全区域。
- 主要触控目标尺寸不小于 44 × 44 CSS 像素。
- 自动跟随系统浅色/深色模式。
- 页面刷新后能根据 URL 恢复当前目录或文件。
- 视频允许 iOS 内联播放，并支持系统全屏播放器。

### 3.2 明确不做

- 上传、下载、编辑、删除、移动、复制或重命名文件。
- 修改 Markdown、DOCX 或其他文档。
- 解压或在线浏览压缩包。
- 音视频实时转码。
- 用户注册、多租户和细粒度权限管理。
- 公网暴露和内置穿透服务。
- 文件内容全文索引。
- 原生 iOS App。

“不提供下载入口”是产品约束，而不是数字版权保护。只要浏览器能够读取文件内容，具备技术能力的访问者就可能保存响应，因此服务仍只应开放给可信局域网。

### 4.3 配置格式

配置文件使用 YAML。Windows SMB 自动发现默认在示例配置中启用：

```yaml
server:
  host: "0.0.0.0"
  port: 8000

shares: []

discovery:
  windows_smb: true

visibility:
  show_hidden: false
  ignored_names:
    - ".git"
    - "__pycache__"
```

配置原则：

- 自动发现的共享使用不可逆、稳定的内部 ID，页面只显示 Windows 共享名称。
- 手动目录的 `id` 用于 URL 和 API，必须唯一且只包含安全字符。
- `name` 用于页面展示，可以使用中文。
- `path` 仅在服务器本地读取，API 不返回该值。
- 实际配置文件不提交版本控制；仓库只提供示例文件。
- Windows 共享权限和 Cross Read 的 HTTP 权限是两个边界：不论 SMB 是否允许写入，Cross Read 始终只提供读取接口。

### 4.4 API 草案

统一响应错误至少包含稳定错误码和用户可读消息。

#### 获取服务信息

```http
GET /api/v1/status
```

用于前端确认服务状态和版本，不返回敏感环境信息。

#### 获取共享目录

```http
GET /api/v1/shares
```

示例响应：

```json
{
  "items": [
    { "id": "documents", "name": "文档" },
    { "id": "courses", "name": "课程视频" }
  ]
}
```

#### 浏览目录

```http
GET /api/v1/shares/{share_id}/entries?path=notes/english
```

示例条目：

```json
{
  "name": "lesson-01.md",
  "path": "notes/english/lesson-01.md",
  "kind": "markdown",
  "is_directory": false,
  "size": 18320,
  "modified_at": "2026-08-26T10:30:00+08:00"
}
```

#### 递归搜索

```http
GET /api/v1/shares/{share_id}/search?q=lesson&path=notes
```

搜索指定目录及其所有子文件夹的文件名，结果中的 `path` 是共享根目录内的相对路径；服务最多返回 500 个结果，并对目录遍历数量设置上限。

#### 读取文件

```http
GET /api/v1/shares/{share_id}/content?path=notes/english/lesson-01.md
```

后端设置正确的 `Content-Type`、`Content-Length`、缓存策略和内容安全相关响应头。

Markdown 内的相对图片也通过同一个受保护的内容接口读取，且必须执行相同路径校验。

#### 播放媒体

```http
GET /api/v1/shares/{share_id}/media?path=videos/lesson-01.mp4
Range: bytes=1048576-
```

媒体接口支持：

- `HEAD` 请求
- `Accept-Ranges: bytes`
- 单区间 `Range` 请求
- `206 Partial Content`
- 正确的 `Content-Range` 和 `Content-Length`
- 无效区间返回 `416 Range Not Satisfiable`

第一阶段不要求 multipart 多区间响应。

### 4.5 前端路由草案

```text
/                         共享目录首页
/browse/:shareId          目录浏览
/preview/:shareId         文件预览，通过查询参数携带相对路径
/about                    服务说明与连接信息
```

路径必须使用 URL 编码，不使用字符串拼接生成请求地址。

### 4.6 文件类型识别

后端结合扩展名和 MIME 类型返回统一的 `kind`：

```ts
type FileKind =
  | "directory"
  | "markdown"
  | "pdf"
  | "docx"
  | "spreadsheet"
  | "presentation"
  | "image"
  | "text"
  | "audio"
  | "video"
  | "unsupported";
```

前端只根据 `kind` 选择预览器，避免在多个组件中重复维护扩展名规则。

### 4.7 音视频兼容策略

- MP4 和 MOV 是容器格式，能否播放取决于内部视频和音频编码。
- WAV、M4A 等音频同样取决于浏览器是否支持文件内部编码。
- MVP 直接提供原文件，不探测或转换编码。
- iOS Safari 最稳妥的组合是 MP4 容器、H.264 视频和 AAC 音频。
- 浏览器报告无法播放时，页面展示兼容性提示，不进入无限加载状态。
- 音视频响应必须支持 Range，否则大文件拖动和恢复播放可能失败。

## 5. 安全设计

### 5.1 路径访问规则

所有文件访问必须经过同一套服务器端路径解析函数：

1. 根据 `share_id` 找到 Windows 当前共享或手动配置的根目录。
2. 将客户端相对路径与根目录组合并规范化。
3. 解析最终真实路径。
4. 确认最终路径仍位于该共享根目录内。
5. 拒绝绝对路径、盘符注入、`..` 越界和符号链接/目录联接绕过。
6. 确认目标存在且具有预期类型后才读取。

路径安全不能只依靠删除字符串中的 `..`。

### 5.2 只读约束

- API 仅提供 `GET`、`HEAD` 和必要的 `OPTIONS`。
- 不实现写入、删除和文件管理接口。
- 业务代码仅以只读方式打开文件。
- 共享目录建议在操作系统层面也使用只读权限运行服务。

### 5.3 内容安全

- Markdown 渲染后的 HTML 使用 DOMPurify 净化。
- 默认不执行 Markdown 中的原始脚本和危险 URL。
- SVG 等可能包含活动内容的资源应使用安全响应头并验证展示方式。
- API 错误不返回电脑绝对路径、调用栈或配置内容。
- 对文本、Markdown、DOCX 等需要完整加载到内存的预览设置大小上限。
- PDF 和视频采用流式读取，避免一次性装入内存。

### 5.4 网络边界

MVP 定位于可信家庭局域网，默认不解决公网安全访问。Windows 防火墙规则应只放行所需端口和合适的网络配置文件。

如果未来需要在外网使用，应通过 Tailscale 或 WireGuard 等私有组网实现，不建议在路由器上直接映射服务端口。

## 6. 界面与视觉规范

### 6.1 设计方向

界面采用类似 iOS 的简洁、克制风格，但不复制 Apple 商标或专有资源：

- 系统字体栈优先使用 `-apple-system`、`BlinkMacSystemFont` 和平台回退字体。
- 通过字体大小、字重和留白建立层级。
- 使用圆角卡片、细分隔线和柔和阴影。
- 顶部工具栏可使用适度的半透明与背景模糊。
- 图标使用统一的开源线性图标集，不使用 Emoji 充当操作图标。
- 动效简短，并尊重 `prefers-reduced-motion`。
- 正文阅读宽度受控，桌面端不把长文本铺满整个屏幕。

### 6.2 响应式布局

#### 手机

- 单列文件列表。
- 顶部显示返回操作、当前标题和必要菜单。
- 文件预览尽量占满可用宽度。
- 底部操作区使用 `env(safe-area-inset-bottom)`。
- 横屏时仍能访问导航和播放器控制。

#### 桌面

- 内容居中并限制最大宽度。
- 可在较宽窗口展示侧栏或更丰富的文件元数据。
- 保持与移动端一致的视觉语言和路由行为。

### 6.3 页面状态

每个页面都需要明确处理：

- 首次加载
- 空目录
- 文件不存在或已移动
- 无权访问
- 网络断开
- 不支持的格式或编码
- 解析失败
- 文件过大而不允许完整预览

## 7. 性能约束

- 目录列表采用按需读取，不递归扫描整个共享目录。
- 大文件必须使用流式响应。
- 视频分块读取，不能将完整视频读入内存。
- 前端按文件类型懒加载 PDF、DOCX 等较重的预览模块。
- 对同一目录的快速重复访问可使用短期缓存，但文件变化后必须能够刷新。
- 搜索只匹配文件名，不建立全文索引；默认筛选当前目录，也可按需递归遍历当前目录及其子文件夹。
- 递归搜索设置结果数量和目录遍历上限，避免超大共享目录占满服务资源。

## 8. 错误处理与可观测性

- 服务启动日志显示版本、监听地址、配置是否有效和共享目录数量。
- 不在普通日志中打印共享目录的文件内容。
- 路径拒绝、文件不存在、Range 无效等情况使用稳定错误码。
- 前端把技术错误转换成简洁、可操作的中文提示。
- 开发环境保留详细日志，生产模式不向客户端暴露堆栈。

## 9. 测试策略

### 9.1 后端自动化测试

- 配置加载与校验。
- 正常目录浏览和排序。
- 中文、空格、特殊字符文件名。
- `..`、绝对路径、盘符和编码变体的路径穿越测试。
- 目录联接或符号链接越界测试。
- 正常文件流和 MIME 类型。
- 音视频完整响应、起始 Range、结束 Range、后缀 Range 和无效 Range。
- 不存在、无权限和类型不匹配的错误响应。

### 9.2 前端自动化测试

- 文件类型与预览组件映射。
- 路由参数和路径编码。
- 加载、空目录和错误状态。
- 文件大小和日期格式化。
- Markdown 危险内容净化。

### 9.3 手工设备验收

- 当前主流 iPhone Safari 竖屏和横屏。
- Windows 上的 Chrome 或 Edge。
- 含中文、空格和长文件名的目录。
- 大体积 MP4 的首播、拖动、暂停和恢复。
- 深色模式与浅色模式。
- 局域网短暂断开后的错误提示。

## 10. MVP 验收标准

满足以下条件即可认为第一阶段完成：

1. 用户能使用 `uv` 安装依赖并启动服务。
2. 服务能读取配置中的多个共享目录，且不泄露真实绝对路径。
3. iPhone Safari 能浏览多级目录并返回上级。
4. Markdown、PDF、DOCX、常见图片和文本能够进入对应预览页。
5. 兼容编码的 MP4/MOV 可以播放并拖动进度。
6. 所有访问均限制在共享目录内部，路径穿越测试通过。
7. 页面不存在上传、编辑、删除、移动和重命名入口或接口。
8. 页面在 iPhone 竖屏下无横向溢出，主要操作易于触控。
9. 浅色、深色模式均清晰可读。
10. README 包含从零启动和手机连接步骤。

## 12. 已确认决策

- 产品定位：自动聚合 Windows 共享目录的局域网只读文件阅读器。
- 第一阶段目标：能够稳定浏览和阅读，不扩展为完整 NAS。
- 后端：FastAPI。
- Python 包和项目管理：uv。
- 前端：Vue 3 + TypeScript + Vite。
- 前端开发依赖管理：pnpm；生产运行不依赖 Node.js。
- 样式：移动端优先的自定义 iOS 风格，不依赖大型 UI 框架。
- 部署：Vue 构建产物最终由 FastAPI 统一提供。
- 默认访问模式：可信家庭局域网，无账号；认证作为后续增强能力。
- Windows 共享发现：启用；刷新首页时与系统共享列表同步，并排除管理共享。
